# M-SPACE 9차 회의 정리 (멘토 점검: 관리자 화면 · 무인 운영 · 수치로 증명)

Nov 9, 2026 · @나영준 · 녹취(음성 인식) + 영준 메모 정리

> **참석자 표기:** 녹취에 이름이 거의 없다. 역할로만 적는다. **멘토**(점검과 조언), **팀**(시연·질문). 앞부분은 점검 전 팀끼리 관리자 화면을 보며 나눈 대화, 끝부분은 영준이 점검 뒤 남긴 메모다. 세 부분을 나눠 적는다.
> 음성 인식 오타는 고쳐 적었다: 엠스페이스·엑스페이스 → M-SPACE, 혹독 → (AI가) 해 둔 것, 수현 → 수연, 재훈·재용 → 재웅(추정), iOS·아이오스 데이터 → IoT 데이터, 이상식·이상치 담지 → 이상 탐지, 제스니 → 젯슨, 크루단·클로드 → Claude, 싱가폰·침과 몰입 → 심각한 오류(추정), 문상 → 문장, 택시 뜨고 → 텍스트 뜨고, 편집 → 상습(추정).
> 같은 날 아침 회의(Q-22·Q-23 결정)는 따로 기록하지 않았고 [요구사항 명세](../requirements/requirements.md) 변경 이력 v0.4.26·v0.4.27에 반영돼 있다. 이 문서는 그 뒤 멘토 점검이다. 멘토가 보여 준 자기 작업(4컷 만화 생성)은 우리 프로젝트와 관계없어 **방법론만** 적었다.

## 한눈에

| 주제 | 한 줄 |
| --- | --- |
| 평가 | 프론트만 계속 만들었다. **"되는 걸 만들어 놓은 것"이라 보여 줄 게 없고 새롭지 않다.** 이번 주는 AI로 사람을 대신하는 것과 그걸 **수치로 보여 주는 것**에 집중 |
| 무인 운영 | 방을 빌려줄 때 있던 **담당자를 없앤다는 생각으로** 만든다. 관리자 화면은 있되 **관리자가 손대지 않게**: AI·규칙이 처리하고, 사람이 꼭 필요한 일만 넘긴다 |
| 관리자 화면 | 학과실 직원은 그래프·지표를 신경 쓰지 않는다. 지금은 "기상청 데이터 센터" 같다. **메인은 현황·신고·할 일만**, 그래프는 **발표용**으로 분리 |
| 관제 에이전트 | IoT 센서로 누가·얼마나·비었는지, 시간이 지났는데 안 나갔는지, CO2 임계치(환기), 퇴실 안내, 실제 몇 명이 썼는지, 상습 위반자 예약 제한까지 **사람 하던 일을 에이전트가** |
| 두고 간 물건 | 별거 아닌 것 같지만 **아주 유용하다**(멘토가 가장 강조). 고정 카메라로 입실 전·퇴실 뒤 같은 장면을 비교해 **달라진 곳만** 잘라 알린다. 물건 이름을 맞힐 필요는 없다 |
| 수치로 증명 | "모델 붙였습니다"는 아무도 안 믿는다. **대상 몇 가지 → 평가 기준 → 모델 후보 비교 → 프롬프트·추론 파라미터 튜닝 → (필요하면) 파인튜닝**, 단계마다 점수를 기록해 보여 준다. 70–80%짜리는 아무도 안 쓴다 |
| 젯슨 메모리 | 8GB 보드 → 실제로 **6GB 안쪽** 모델만 후보 |
| 음성 | 사용자가 글을 치게 만들면 AI 시대에 맞지 않다. **말로 주고받는 비서.** 대신 뒤의 구조(STT 품질, 실시간 변환, 도구 선택)를 설명할 수 있어야 한다 |
| 대화형 예약 | "몇 명이서 하실 거예요?" → "나 포함 4명" → "나머지 3명이 누구예요?" → 이름을 말하면 예약 + 친구들에게 메시지. **회장님처럼 까딱 안 해도 되는** 비서 |
| 지켜보다 잡아 주기 | 대기열에 줄 세우기보다, **비서가 지켜보다가 비는 순간 대신 잡아 주는** 그림(최저가 알림처럼). 취소 가능성은 수치 분석이라 꼭 AI가 아니어도 된다 |
| 시간표 확장 | 아침에 "오늘 몇 시 무슨 수업, 숙제 남았어요". 친구 한 명이 숙제·휴강을 등록하면 **AI가 판단해 친구들에게 퍼뜨리기** |
| 서비스 이름 | 앞에 M-SPACE를 붙이지 말 것. M-SPACE만 하는 것처럼 보인다. **비서 이름을 따로** |
| 발표 | 쇼맨십도 필요. 만든 것을 잘 포장한다. 관리자 화면이 복잡하다는 질문엔 **"A·B·C 코스를 다 준비했다"**(팀 대화) |
| 기한 | **이번 주 금요일(11/13)까지 결과물**, 월요일(11/16) 접수 |

## 1. 점검 전 팀 대화: 관리자 화면 보기

| 의견 | 내용 |
| --- | --- |
| 너무 복잡 | 학과실 직원이 볼 화면인데 그래프·지표가 메인에 나오면 복잡해 보이고 처리하기 싫어진다. "기상청 데이터 센터 같다", "정신없다, 뭘 해야 할지 모르겠다", "UI가 너무 AI스럽다"는 말을 다른 사람에게서도 들음 |
| 좋은 점 | **할 일 목록**(18시 퇴근 뒤 AI가 맡고, AI가 혼자 못 하는 일만 관리자에게 넘김)은 잘 됐다 |
| 데이터 | 지금 값은 모의 값이다. 실제 센서·AI와 연결해야 한다 → 관리자가 **딸깍 한 번**으로 처리하게 |
| CO2 보여 주기 | 그래프 대신 **"어제 이 시간보다 N 높습니다"** 한 줄 + "제가 할게요" **[예]/[아니요]** 정도만 |
| 가독성 | 간격을 넓히고, 빽빽한 글씨를 줄인다. 그래프는 오직 발표용 |
| 대시보드 | 실제로는 안 볼 것 같지만 지난 점검에서 "넣으라"고 해서 넣었다. 발표 때 보여 주기는 좋다 |
| 질문 대비 | "복잡하지 않나요?" → "어떤 걸 좋아하실지 몰라 A·B·C 코스를 준비했습니다. 이게 별로시면 B 코스로 보여 드리겠습니다"(오마카세처럼) |
| 아침 조언 | 관리자 페이지는 있지만 **관리자가 손을 대면 안 된다**. AI를 시키든 조건값으로 자동 처리하든 |
| 센서 | 수연이 온도·습도를 연결하는 중(수업 때 해 본 시계열 실습과 같은 방식) |

## 2. 멘토 피드백 자세히

### 2.1 비서는 말로 주고받는다

- 텍스트가 뜰 수는 있지만 **말로 대화하듯이**. 확인 창이 뜰 수는 있어도 사용자가 계속 글을 치게 만들면 안 된다
- 예약 대화 예: "몇 명이서 스터디 하실 거예요?" → "나 포함 4명" → "4명으로 잡을게요. 나머지 3명은 누구예요?" → 이름을 말하면 바로 들어가고 "친구들에게도 메시지 보내 둘게요"
- 시간표: 에브리타임 캡처를 넘기면 바로 옮겨진다(이미 있음, 시험해 볼 것). 직접 입력도 가능
- 발표에서는 "말로 이렇게 됩니다"보다 **뒤에 MCP 구성이 있고, 음성을 텍스트로 바꾸고(모델 품질 문제, 실시간 변환), AI가 판단해 도구를 고르고 결과를 준다**는 과정을 보여 줘야 한다. 텍스트 답의 지연도 문제로 안다
- 답을 음성으로 주는 건 웹에서 재생해야 해서 어려울 수 있다(멘토). 텍스트로 줘도 된다

### 2.2 담당자를 없애는 무인 운영 (관제 에이전트)

- IoT는 "발표에 내세울 게 아니다"는 팀 말에 멘토는 반대: 센서가 있으면 할 수 있는 게 많다

| 에이전트가 하는 일 | 근거 |
| --- | --- |
| 방 상태(누가·얼마나·비었는지) 알리기 | 재실·CO2 센서 |
| CO2 임계치 → 환기 안내 | 환경 센서 |
| 시간이 지났는데 안 나감 → 퇴실 안내 | 예약 종료 + 재실 |
| 실제로 몇 명이 몇 분 있었는지 | 재실·인원 |
| 상습 위반자 골라내고, 쌓이면 예약 제한 | 노쇼·경고 기록 |
| 쓰레기·두고 간 물건 → 알림 | 카메라 전후 비교 |

- "관리자가 클릭해서 보는 것"은 의미 없다, 관심 없다. **IoT 데이터를 써서 에이전트 쪽에서 진짜 사람이 하듯이**
- 정리하면 에이전트 두 개: ① **관제 에이전트**(센서·이상 탐지, 팀 아이디어) ② **음성 비서 에이전트**(MCP로 데이터를 가져와 비서처럼)

### 2.3 두고 간 물건 탐지 (이상 탐지)

- 원래 사진(입실 전)과 나간 뒤 사진을 같은 고정 카메라로 비교 → **새로 생긴 물체 / 안 보이는 물체** 부분만 잘라 "안 가져가셨어요" 알림
- 굳이 "노트북이에요"라고 이름을 맞힐 필요 없다 → **틀릴 일이 줄어든다**
- 세상 모든 물건은 어렵다. **텀블러·노트북·가방·핸드폰처럼 작은 것·큰 것 몇 가지만** 정해 수치를 올려 본다
- 멘토 경험담: 도서관 책상에 CD 플레이어와 CD 100장을 두고 갔다가 순식간에 잃어버림. 300만 원짜리 노트북이라면? → 이 기능의 쓸모

### 2.4 수치로 증명하기 (가장 길게 강조)

| 단계 | 할 일 |
| --- | --- |
| 1. 대상 정하기 | 몇 가지 물건만 |
| 2. 평가 기준 | 정확도, **심각한 오류 0건**, 한 번 판단에 걸리는 시간, 메모리 |
| 3. 모델 후보 비교 | 여러 모델을 같은 조건으로 시험. 젯슨 8GB → 80% 정도, **6GB 안쪽** |
| 4. 선정 | 기준을 넘는 모델 채택 |
| 5. 프롬프트 튜닝 | 프롬프트를 바꿔 가며 점수 기록 |
| 6. 추론 파라미터 | 깊게/가볍게 생각하는 값 등 모델마다 있는 값 조절 |
| 7. 파인튜닝(필요하면) | 방에서 텀블러·빵·노트북 사진을 찍어 라벨을 달아 기존 모델에 추가 학습 → 다시 측정 |
| 8. 여러 모델 | 하나로 안 되면 두 모델을 같이 써서 둘 다 감지하면 확률이 높다고 보는 방식 |

- "해 보면 80–90%까지는 금방 간다. **나머지 10–20%에서 품질이 결정된다.** 공장 품질 검사가 70–80%면 쓰겠나? 사람은 99.9%를 원한다"
- 모델 연구가 아니라 **있는 모델(허깅페이스 등)을 실제 서비스에 붙여 품질을 끌어올리는 능력**이 중요하다. 시행착오와 몇 %까지 올렸는지를 기록해 두면 발표·포트폴리오에 쓴다
- 멘토 사례(방법론만): 그림 모델 후보를 속도·메모리·점수로 비교해 하나를 고르고, 프롬프트 판을 바꿔 가며 91.5점 → 97점대까지 올림. 판을 올린다고 늘 오르지는 않았고(8판이 9·10판보다 좋음), **심각한 오류 0건**을 점수보다 먼저 지킴. 컷당 시간(27초 → 5.4초)도 기준. 95–97점에서 정체 → 타협 지점을 정함
- Spring 같은 개발 능력(AI가 짠 코드를 읽고 잘못을 지적하는 능력)도 여전히 중요하다. 다만 **이 프로젝트에서는** AI를 실제 서비스로 만든 타당성을 보여 줘야 한다

### 2.5 지켜보다 잡아 주기와 취소 가능성

- 팀 아이디어: 4–5시를 쓰고 싶은데 이미 잡혀 있으면 대기를 걸고, 취소되면 바로 알린다
- 멘토: 대기열 밑에 줄을 세우기보다 **비서가 계속 지켜보다가 "비었네" 하고 대신 들어가는 것**이 비서다. 쇼핑몰 최저가가 뜨는 순간 사는 것과 같다(먼저 본 사람 순서인 대기열이 더 맞을 수도 있다는 말도 함)
- 먼저 예약한 사람의 취소 기록·시간표로 "이 사람은 취소할 확률이 있다"를 보여 줄 수도 있다. **수치 분석이라 꼭 AI가 아니어도 된다**

### 2.6 시간표 확장과 친구 공유

- 아침에 일어나면 "오늘 몇 시 무슨 강의, 숙제 남았어요"
- 친구 한 명이 숙제나 "3시 수업 휴강"을 등록하면 친구 전체에게 퍼진다. **AI가 이게 알려야 할 메시지인지, 혼자 간직할 메시지인지 판단**
- 팀 질문 "M-SPACE 목적이 있는데?" → 멘토: 먼저 그쪽(M-SPACE)을 만들고 **확장해서 보여 주면 된다**. 기능은 한 사람씩 맡아 따로 만드는 게 낫다(같이 하면 코드가 꼬인다), 서로 크로스 체크

### 2.7 이름과 발표

- 제목 앞에 M-SPACE를 붙이면 M-SPACE만 하는 서비스처럼 보인다. 비서 이름을 따로 지어 보라("스페이스 ○○"처럼)
- 발표는 쇼맨십도 필요하다. 없는 걸 말하는 게 아니라 **만든 걸 잘 포장하는 것**도 능력
- 이번 주 금요일까지 결과물, 월요일 접수. 되면 또 가져와서 보여 달라
