# M-SPACE 10차 회의 정리 (강사님 피드백: 사람이 필요 없는 스터디룸)

Nov 10, 2026 · 재웅 정리(녹음 받아쓰기 + 회의 뒤 팀 대화)

> 받아쓰기가 흐린 곳은 "확인 필요"로 적었다. 강사님이 보여 준 자기 작업(4컷 만화 생성)은 우리 프로젝트와 관계없어 **방법론만** 적었다.
> 요구사항 반영: [요구사항 명세](../requirements/requirements.md) v0.4.32(경고 철회 요청)·v0.4.33(이 회의).

## 한눈에

| 주제 | 결정 |
| --- | --- |
| 방향 | **"사람이 필요 없는 스터디룸".** 관리자는 **아무것도 하지 않는다.** 웹 관제 대시보드로 보기만 하고, 경고 부여·판단·철회 재검토는 전부 AI(재웅 확정) |
| 발표 목표 | AI 판단 **신뢰도를 숫자로 올린 과정**을 표로: 모델 비교·지시문 개선·학습으로 예) 70% → 90% |
| 가상 기기 | 실제 에어컨·공기청정기는 API가 없다 → **가상 기기** + **파사드·어댑터**로 "실제 기기로 바꿔 끼울 수 있다"를 보여 준다 |
| 센서 | **수집 + 이상치 탐지(CO2 등)까지만.** 가상 센서 ↔ 실제 센서도 같은 구조. MQTT 공부 |
| 환기 | CO2가 높으면 관리자 말고 **방 사용자에게 바로** 환기 알림 |
| 두고 간 물건 | 종류 구분 없이 **"두고 갔다"만**(정확도 목표 95%). **"제 거 아니에요" 버튼 제거.** **2시간 안에 안 가져가면 경고** |
| 사진 원칙 | "사진 남기지 않기"는 **사람 기준.** 빈 방·물건 사진은 저장 가능 |
| 경고 철회 | 경고 받은 뒤 **7일 안** 철회 요청, **AI가 다시 비교**(지영 제안, 재웅 확정, FR-RPT-105) |
| 관리자 화면 | **관리자 앱은 만들지 않는다.** 지금 있는 관리자 페이지를 쓰고, 디자인은 재웅이 나중에 정함 |
| QR | QR 밑 **숫자 숨김** |
| 비서 | 성향 모드(잔소리·조용히)보다 **대화 품질 먼저.** 점수 기준표로 지시문을 조금씩 개선 |
| 음성 | "에어컨 켜 줘" → (가상) 기기가 바뀌고 대시보드에 보임. **온도 취향 학습은 하지 않음** |
| 시뮬레이션 | 가상 시나리오(예약 → 입실 → CO2 상승 → 기기 자동 켜짐 → 대시보드)로 시연 |

## 1. 강사님 피드백

### 1.1 무인 운영

- "어질러져 있어요. 경고를 줄까요? 예/아니오"처럼 **관리자에게 묻지 않는다.** 정량 기준을 정해 AI가 자동으로 경고한다(성적처럼 중대한 일만 사람이 확인)
- 에어컨·공기청정기도 에이전트가 기준(예: 온도 24도 유지)으로 **알아서 켜고 끈다**
- 관리자는 "잘 돌아가네" 하고 가끔 보기만. 계속 관리자에게 일을 주면 안 된다

### 1.2 가상 기기 + 디자인 패턴

```mermaid
flowchart LR
    core[core<br/>"2번 방 에어컨 켜"] --> facade[기기 파사드<br/>문 하나]
    facade --> v[가상 에어컨 어댑터<br/>노트북 화면 표시]
    facade -.-> lg[LG 어댑터]
    facade -.-> ss[삼성 어댑터]
```

- 공통 인터페이스(켜기·끄기) → 에어컨(냉방·난방·온도 올리기·내리기)·공기청정기 → 가상/LG/삼성 구현
- core는 파사드에 명령만 보낸다. 기기마다 `if LG … else if 삼성 …`을 늘리지 않는다
- 그냥 가상이면 "장난친 거 아니냐"는 말을 듣는다 → **설계로 풀고 발표에서 "확장성"으로 내세운다**

### 1.3 관리자 = 웹 대시보드, 학생 = 모바일 앱

- 큰 화면(30–32인치) 한 장: 방별 온도·습도·CO2·그래프, 방 기기와 상태, 에이전트 조치 기록, 노쇼·자동 퇴실, 시간대별 이용률
- 둘을 섞지 않는다(선택과 집중)

### 1.4 모델 점수 비교

- 좋은 시도. 로컬 모델(젯슨·8B 등)이 50% 정도로 낮아도 억지로 올리지 말고 **기록**한다 → "기준 미달이라 Gemini Flash Lite 선택"처럼 근거로 쓴다. 제약(예: 1분 15건)도 적는다
- 8B → 12B로 조금만 오르면 가벼운 모델 최적화를 택한다(비용 줄이며 성능 내기)
- 방법론(강사님 사례): **한 번에 다 하지 말고 단계별로.** 기본이 되면 점수 기준표를 만들고, 돌려 보고, 놓친 걸 찾아 지시문을 고치고, 다시 잰다

### 1.5 그 밖

- 카메라 2개: 방 안(두고 간 물건) / 문 앞(QR). 방마다 시연할 수 있게
- 시간표 캡처는 Gemini 그대로(모델 이름은 녹음에서 섞여 들림, 확인 필요). 사용자 API 토큰 방식도 선택지
- CO2 센서: 강사님이 신호 확인 뒤 수집 방법을 알려 주기로 함

## 2. 회의 뒤 팀 대화

- 두고 간 물건: 탐지 정확도 95%면 잘못 찍힐 일이 거의 없어 "제 거 아니에요" 버튼을 없앤다. 쓰레기든 가방이든 안 가져가면 경고. M-space 원래 규칙도 위반하면 이용 불가라 깐깐해도 된다
- 가져갈 시간: 24시간 이야기도 나왔지만 **2시간**으로. 다음 날 본인이 다시 예약해 가져가도 된다. 가져가러 들어가는 방법(버튼 누르면 10분, 한 번 더 3분)은 이야기만 나옴(Q-27)
- 사진 원칙은 초상권 때문에 **사람 기준**. 물건·빈 방은 입실 전·퇴실 뒤라 사람이 없다 → docs 문구 고치기(v0.4.33)
- 센서 코드가 한 센서에 맞춰져 있다 → 여러 센서가 붙게 패턴으로 바꾸기
- 지영 제안: 경고 철회 요청 7일(→ 재웅 확정, 재검토는 AI)
