## Nginx 매니저 실습

- 멘토가 만든 Nginx 설정 관리 도구를 팀 계정으로 받았다. 사이트(도메인) 추가 → 리버스 프록시 → 내부 IP(10번대)·포트 입력 → Let's Encrypt 인증서 → HTTP를 HTTPS로 넘기기 → 저장·적용·reload.
- 요청 흐름: 도메인 → DNS → 공인 IP(220번대) → 학교 내부 IP(10번대) → 포트 → 애플리케이션. 포트는 한 서버 안의 여러 애플리케이션을 구분한다.
- 실습 중 500·502가 난 경우는 포트가 다르거나 애플리케이션이 떠 있지 않은 경우였다.
- 서브 도메인은 멘토에게 요청하거나 직접 사도 된다.

## 저장소별 영향

| 저장소 | 할 일 | 담당 |
| --- | --- | --- |
| `infra` | 아키텍처 그림 수정(서비스 이름, 내부 네트워크 경계, Nginx 하나). 게이트웨이 도입 여부 결정. MCP 서버를 바깥에서 닿지 않게 | 재웅 |
| `core` | 공개·인증 필요 엔드포인트 규칙(게이트웨이가 없으면 core의 보안 설정에서). 메일 발송 비동기 | 지영 |
| `mspace-assistant` | 채팅 API를 **요청 접수 → 결과 조회(폴링)** 방식으로. 이렇게 하면 지금의 "45초 기한 + nginx 60초 제한" 문제가 함께 풀린다. MCP는 내부 포트만. CO2 환기 알림 도구는 IoT 수신기 뒤에 | 영준 |
| IoT | 센서 수신 공통 인터페이스(예: CO2 수신) + 센서별 구현. 레이저 센서 도착 전에는 가상 센서 데이터로 | 수연 |
| `front` | 관리자·사용자 화면 통합. 채팅 화면은 폴링 | 재웅(화면) |
