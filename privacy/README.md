# M-SPACE 개인정보 처리방침 (초안)

> 상태: **초안 v0.1** (2026-11-05, 영준 작성 · Claude Code 보조). 팀 확인 → 11/20 발표 전 앱 "이용 규칙" 옆에 붙이는 것이 목표.
> 법 문구가 아니라 **우리가 실제로 어떤 데이터를 왜·어디에·얼마나 두는지**를 학생 눈높이로 적은 것. 항목·기간은 코드·요구사항 명세(FR/NFR)와 맞춰 두었고, 다른 곳이 있으면 이 문서가 아니라 요구사항을 기준으로 고친다.
> **시연·경진대회 단계에서는 실제 학생 정보를 쓰지 않고 테스트 계정(99999001~)만 쓴다.** 학교가 도입하면 교학팀·학교 개인정보 담당과 함께 정식 문구로 바꾼다 (확인 필요).

## 1. 누가, 무엇을 위해

| 항목 | 내용 |
|---|---|
| 운영 주체(시연) | 조선대 IT융합대학 캡스톤 팀 AI-go-do (개인 프로젝트 단계. 학교 도입 시 교학팀) |
| 목적 | ① M-space 회의·스터디 방 예약 ② 예약한 사람만 들어가게 하는 출입(6자리 번호) ③ 노쇼·자리 비움 자동 처리 ④ 이용 수칙 위반 신고·판정 ⑤ 예약 알림 ⑥ AI 비서가 예약을 대신 처리 |
| 근거 | 학생이 가입·예약 때 동의(이용 규칙 동의 화면, FR-WEB-001). 학교 도입 시 학칙·시설 이용 규정에 따름 (확인 필요) |

## 2. 무엇을 모으나

| 구분 | 항목 | 어디서 | 왜 | 요구사항 |
|---|---|---|---|---|
| 회원 | **학교 메일, 이름, 학번** | 학교 메일 인증 가입 | 본인 확인, 대표자·참여자 표시 | FR-AUTH-001, NFR-COM-003 |
| 로그인 | 액세스 토큰(1시간), refresh 토큰(14일, **해시로만** 저장) | 로그인 | 자동 로그인 | FR-AUTH-002 |
| 예약 | 방, 시작·끝 시각, 대표자, 참여자 학번, 상태(BOOKED·IN_USE·CHECKED_OUT·NO_SHOW…), 만든 경로(WEB/AGENT/DEVICE) | 예약·즉시 시작·연장 | 예약 규칙 적용, 중복 방지 | FR-RSV-* |
| 친구 | 친구 관계(두 학생), 보낸·받은 요청과 수락 시각 | 친구 화면 | 참여자는 서로 수락한 친구만 넣기 | FR-RSV-004 |
| 출입 | 6자리 입실 번호(예약마다), 키패드 입력 성공·실패 시각 | 키패드 | 문 열기, 5회 실패 잠금 | FR-ACC-001 |
| 재실 | 방 안 **레이더·조도·CO2 수치**(사람 수·얼굴 아님) | 방 센서 | 자리 비움 자동 퇴실, 환기 알림 | FR-DEV-* |
| 사진(선택) | 체크인·퇴실 때 학생이 직접 찍은 **방 사진**과 찍은 시각 | 학생 폰 | 정리 상태 증빙(분쟁 때) | FR-RPT-102 |
| 신고 | 신고 종류, 내용, 신고한 사람, 대상 예약, 관리자 판정·경고·정지 기록, 관리자 강제 퇴실 사유(이름·학번은 쓰지 않게 안내) | 신고 화면 | 수칙 위반 처리(30일 3회 경고 → 14일 정지) | FR-RPT-101·103 |
| 알림 | 메일 주소(위 회원 정보), 웹 푸시 구독 정보(브라우저가 주는 endpoint·키) | 알림 설정 | 시작 전·노쇼 임박·자리 비움 알림 | FR-NTF-* |
| AI 비서 | 학생이 비서에 **쓴 말(가린 글)**, 비서가 부른 도구 이름·결과, 학생이 직접 넣은 **시간표(요일·시각·과목명)** | 채팅 화면, 내 시간표 화면 | 대화 이어 가기(24시간), "수업 끝나고" 계산 | FR-AGT-101·102 |

**모으지 않는 것**
- 카메라 영상·얼굴·음성 (재실은 센서 수치로만, 요구사항 "카메라 없이")
- 전화번호, 주소, 생년월일, 결제 정보
- 위치 정보 (앱은 위치 권한을 요구하지 않음)
- 비서 대화의 **원문**, 로그인 토큰, 입실 번호는 비서 서버가 기억하지 않음 (아래 4장)

## 3. 어디에, 얼마나 두나

| 데이터 | 저장 위치 | 보관 기간(안) | 지워지는 때 |
|---|---|---|---|
| 회원(메일·이름·학번) | core PostgreSQL (학교 실습 서버, 외부에 열지 않음) | 재학 중 | 탈퇴 요청 즉시, 또는 학교 도입 시 졸업·제적 명부 반영 (확인 필요) |
| 친구 관계·요청 | core DB | 학생이 친구를 끊을 때까지 | 끊으면 양쪽에서 바로 빠짐(이미 잡은 예약의 참여자는 그대로) |
| refresh 토큰 해시 | core DB | 마지막 사용 후 14일 | 로그아웃 즉시 |
| 예약·출입·노쇼 기록 | core DB | **1학기(6개월)** 뒤 익명화(학번 제거) 안 | 제재 근거라 바로 지우지 않음. 기간은 팀 결정 필요 |
| 경고·이용 정지 | core DB | 정지는 14일, 경고 집계는 30일 창 | 그 뒤 집계에서 빠짐. 기록 자체 보관 기간은 위와 같음 |
| 방 사진 | core DB(PostgreSQL `bytea`, 11/5 지영 결정). 앱이 900KB 아래로 줄여 보냄 | **30일** 안 | 분쟁 신고가 없으면 지움. 신고가 걸리면 판정 끝날 때까지 |
| 센서 수치 | core DB(시계열) | 원 수치 30일, 집계는 길게 | 사람을 식별하지 않는 값 |
| 비서 대화 맥락 | agent **Redis**, 키 `agent:conv:<학생 키>` | **24시간**(TTL) | 자동 만료, 또는 "새 대화" 버튼 즉시 |
| 비서 시간표 | mcp-server Redis, 키 `agent:schedule:<학생 키>` | 학생이 지울 때까지(TTL 없음) | 내 시간표 화면의 삭제 즉시 |
| 비서 채팅 결과 | agent 메모리 | 5분 | 자동 |
| 서버 로그 | 학교 서버 docker 로그 | 로그 회전(확인 필요: infra 설정) | 개인정보를 쓰지 않으니 기간보다 "무엇을 안 쓰나"가 중요(4장) |

- 숫자는 모두 **안**이에요. 코드에 박지 않고 설정값으로 두고, 팀이 정하면 이 표와 요구사항을 같이 고쳐요.
- "지움"은 시연 서버의 DB 행 삭제·익명화를 뜻해요. 백업이 있다면 백업 회전 주기만큼 더 남아요 (확인 필요: infra 백업 여부).

## 4. 밖으로 나가는 것 (제3자 제공·위탁)

| 받는 곳 | 무엇 | 왜 | 안 보내는 것 |
|---|---|---|---|
| **Google Gemini API**(미국, 외부 AI) | 비서 대화의 **가린 글**(학번·전화번호·입실 번호 모양은 서버가 `[학번]` 등으로 바꿈), 도구 결과(방·시각·상태), 시간표의 **요일·시각·과목명**, 시간표 캡처 **사진**(2단계, 학생이 올릴 때만) | 말을 이해하고 도구를 고르게 | 이름·학번·메일·토큰·입실 번호. 캡처에 이름·학번이 찍혀 있으면 **올리기 전에 잘라 달라고 안내**(완전 차단은 못 함, 한계로 기록) |
| 학교 메일 서버 | 인증 번호, 알림 문장 | 가입 인증·알림 | — |
| 브라우저 푸시 서비스(Google·Apple 등) | 알림 제목·문장 | 웹 푸시 | 이름·학번은 문장에 안 넣음 |

- 학교 도입 시 Gemini 대신 **학교 안 Ollama**(Jetson 보드)로 바꿀 수 있게 `LlmClient` 포트 뒤에 두었어요(NFR-COM-006). 그러면 2행이 "밖으로 나가는 것"에서 빠져요.
- 그 밖에 광고·분석 도구(GA 등)는 쓰지 않아요.

## 5. 우리가 지키는 것 (안전조치)

| 조치 | 어떻게 |
|---|---|
| 권한 검사 | **AI 모델을 믿지 않아요.** 비서는 학생 본인 토큰으로만 core를 부르고, 남의 예약은 core가 403으로 막아요. 관리자·공용 토큰을 쓰지 않아요 |
| 쓰기 두 단계 | 예약·취소·퇴실·연장은 학생이 화면에서 [확인]을 눌러야 실행돼요. 확인 토큰은 1회·짧은 만료 |
| 전송 | HTTPS만(학교 nginx). 토큰은 헤더로만, URL에 안 넣어요 |
| 로그 | 사용자 말 원문·토큰·이름·학번·전화번호를 로그에 안 남겨요. 도구 이름·걸린 시간·성공 여부만 (conventions.md) |
| 비밀값 | 키·비밀번호는 Git에 없고 GitHub Secrets → 서버 `.env`에만 |
| 입실 번호 | 대표자에게만, 화면 카드로만 보여 줘요(모델을 거치지 않음). 퇴실·취소·노쇼 즉시 무효 |
| 다른 사람 이름 | 참여자 목록에서 다른 사람 이름은 일부만 보여 줘요(NFR-COM-003) |
| 시연 데이터 | 실제 학생 정보 대신 테스트 계정(99999001~)과 가짜 데이터만 |
| 접근 | DB는 외부에 열지 않고 서버 안에서만. 관리자 화면은 관리자 계정만 |

## 6. 학생이 할 수 있는 것

| 권리 | 어디서 |
|---|---|
| 내 정보·예약 보기 | 앱 "내 예약", "내 정보" |
| 시간표 지우기 | 앱 "내 시간표" → 삭제 (즉시) |
| 비서 기억 지우기 | 채팅 "새 대화" (즉시, 또는 24시간 자동) |
| 알림 끄기 | 브라우저 알림 권한 해제 |
| 로그아웃 | 모든 토큰 즉시 무효 |
| 탈퇴·삭제 요청 | 시연 단계: 팀 메일(아래). 도입 시: 교학팀 창구 (확인 필요) |
| 신고 기록 이의 | 관리자 판정에 이의 → 관리자 재판정 (FR-RPT-103) |
